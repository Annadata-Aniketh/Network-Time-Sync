THE PROBLEM

Every clock drifts.

Each client has a virtual clock that runs at a slightly different rate. Without correction, their timestamps move apart. One server gives them a common reference.

TRY AN UNEQUAL PATH

The client starts 100 ms ahead; server processing takes 2 ms.

RTT = (t3 − t0) − (t2 − t1)20 ms
offset = ((t1 − t0) + (t2 − t3)) / 2−100 ms

Equal path delays give the correct offset. Residual error: 0 ms.

THE CONTROLLER'S JOB

Give time a clearer path.

Queue treatment and routing work together. The controller reacts to measured traffic load; it does not read the client's clock or directly measure queue delay.

01 / CLASSIFY

Recognize the flow

UDP port 12300 identifies sync traffic. Queue 1 reserves bandwidth at the Path A edge. UDP background traffic enters queue 2, capped at 6 Mbps.

02 / RESPOND

Find another route

Poll s1 port 5 every 2 seconds. At 4 Mbps or above, priority-200 rules move sync requests and replies through s3 on Path B.

03 / RECOVER

Return automatically

Three consecutive polls below the threshold remove the reroute rules. The original Path A rules remain. Flow counters verify that traffic returned.
